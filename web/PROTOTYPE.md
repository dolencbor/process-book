The homepage is a static frontend prototype in the existing Next.js app. It uses local Figma assets and sample data, with no CMS requests on the homepage.

## Performance and regression checks

The shared tab bar stays fixed at y=44 in both views and uses the same 680ms tween and text masks. Stable commands and memoized controls separate tab selection, hover previews, cursor movement, and the visible week. Both views use the same distance-based navigation curve and timing; manual input interrupts a tab trip without changing its position. Initial tab measurement is immediate, so mobile does not resize from an assumed desktop width.

Every tab supplies a pixel `flex-basis` Motion value from the first server render. One shared Motion tween updates all four widths together. Independent width targets previously retained different start times after rapid period changes, briefly contracting the right edge; a regression reproduces a 29px gap after two interrupted selections. Every new selection now stops that shared timeline and retargets all four widths from their actual current values, keeping their sum constant and both outer edges fixed during period changes. Client measurement applies the actual viewport width before paint, and later tab/viewport changes retain the original 680ms tween. Empty ResizeObserver measurements are ignored. The tab-render regression test exercises the actual React/Motion HTML for all four selected periods, so valid sizing calculations cannot conceal missing width styles in the rendered buttons.

The rail renders an eleven-card moving window, including two extra buffers at each end, instead of twenty-eight animated image trees. Every omitted card has zero opacity throughout the original scroll and arrival/exit geometry. Card position uses Motion transforms; animated width/height, image crops, opacity, smoothing, arrival curves, masks, and spring landing remain intact. Layout containment confines card morphing to the stack.

Table row geometry is cached on mount and resize. Scroll and pointer events share one requestAnimationFrame job, with scroll indication preserved when both arrive in the same frame. Pointer moves use the event's row instead of repeated document hit-tests; scroll uses a fresh hit-test. Hover changes re-render only the affected rows and preview. The preview remains outside scroll overflow and below the fixed tabs.

Corner observers cache paint profiles and SVG node references, skip unchanged sizes, and process added/removed subtrees instead of scanning the complete app on every child mutation. Computed-style reads are batched before writes and excluded from size-animation frames. Borderless, unfocused cards no longer encode invisible border/focus images each frame; keyboard focus still draws the same smoothed ring. Responsive radius changes remain supported.

The seven active raster assets use full-resolution lossless WebP, reducing their combined size from 6,972,782 to 1,954,934 bytes (72%). Decoded alpha and every visible RGB pixel were verified against the original PNGs; the original files remain available. Scroll and Table share the same preview URL rather than fetching identical artwork twice, and that artwork is preloaded during server rendering. `npm run assets:optimize` regenerates and verifies these files.

Run `npm run test:interactions` for navigation, preview, layer, corner, responsive sizing, and geometry regressions. Checks use the installed Motion generators and actual component logic with simulated hooks/DOM geometry. They include 639,744 card-geometry samples and a burst of 1,000 mixed pointer/scroll events that produces one frame job, two box reads, and no row-list queries. These are deterministic logic/workload checks, not browser frame-rate measurements. Live Safari rendering and frame-rate verification remain unavailable because the browser's local URL policy blocks this site. Lint, TypeScript, and `npm run build -- --webpack` complete the code checks.
